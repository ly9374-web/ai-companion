# 摄像头可选模块

本目录保存完整的可选摄像头能力。删除整个目录并重新构建前端后，项目会自动使用空实现；聊天、语音、Live2D、屏幕捕获、浏览器面板和后端启动均不依赖本目录。

使用摄像头前先双击 `emotion_camera/start.command`。浏览器只连接本机代理；AK、SK 和临时 Token 不进入前端代码。

## 工作流程

1. 开启摄像头后显示 3 秒全屏蒙版倒计时。
2. 倒计时结束时，以最近约 1.1 秒有效 AU 的中位数建立个人基线；有效数据不足时继续显示蒙版等待人脸稳定。
3. 此后只要摄像头开启，就持续计算 AU 相对基线的正向差值，经短时中位数平滑和个人噪声扣除后，转换为 AU 比例并与表情原型计算相似度；助手说话期间也不会暂停实时计算。
4. 调试模式开启时，画面顶部显示缩小版实时 AU 差值柱状图，右上框显示当前实时表情，右下框显示本轮发送给模型的汇总表情。助手说话时只暂停本轮时长累计，不隐藏或暂停调试界面中的实时结果。
5. 基线完成后立即开始第一轮用户检测。以后在助手播放结束或被用户打断时开始，在用户发送文字或语音时结束。
6. 每轮优先选择有效时长占比最高、且占总有效时长超过 10% 的非中性表情；前两名相差不超过 1 个百分点时发送两个，否则发送一个。没有非中性达到阈值时发送中性。
7. 后端仅向当轮 user prompt 添加：`用户当前的表情为：{用户的表情}`。

## 算法与边界

- 不使用云端直接返回的情绪标签、概率或置信度。
- AU43 可被云端返回，但不参与表情分类。
- 顶部调试图仍显示 AU43；图中绿色为高于个人基线，红色为低于个人基线，数值为平滑后的 `当前 AU − 基线 AU`。
- 顶部 AU 图和右侧两个表情框仅在主应用调试模式开启时出现；关闭调试模式不会停止识别或 prompt 注入。
- “A或B”的实时结果在轮次统计中各计一半时长。
- 无人脸或结果过期的时间不计入有效时长。
- 摄像头图像只以 JPEG 二进制帧发送给 AIE 实时 WebSocket，不在本地保存。
- 网络、协议、摄像头、空结果和识别异常都在模块内降级，不阻止聊天消息发送。
- 短暂断线会自动重连；鉴权恢复后清除重连提示并继续使用已有个人基线。

## 文件

- `optional-feature.json`：可选模块声明及运行参数。
- `frontend-src/index.tsx`：摄像头 Provider、入口、预览和主项目轮次桥接。
- `frontend/`：动态加载的 WebSocket、JPEG、AU 推断、轮次汇总和显示运行时。
- `backend_context.py`：校验浏览器汇总结果并生成当轮 prompt 文案。
- `emotion_camera/`：AK/SK 取临时 Token、WSS 云端连接和本机 WebSocket 转发代理。

# 摄像头可选模块

本目录保存可选的摄像头、屏幕共享和浏览器面板能力。CS 账号规则、快捷话题、角色权限和问候语音已放在共用后端 `src/open_llm_vtuber/account_features.py`，普通启动和摄像头启动都使用同一规则。

主目录的 `启动.command` 默认关闭本模块：不导入 `backend_context.py`，不挂载 `/web-tool`，电脑页面也不加载摄像头代码。`frontend/camera.html` 只在摄像头模式可访问。构建前端时仍会保留摄像头页面供专用启动器使用；缺少本目录时只构建普通电脑页和手机页。

需要摄像头表情功能时，只需双击 `emotion_camera/start.command`：它会先启动本机鉴权代理，再调用项目原有主启动器。项目根目录原来的 `启动.command` 保持不变，仍可正常单独启动主页面。浏览器只连接本机代理；AK、SK 和临时 Token 不进入前端代码。

## 工作流程

1. 开启摄像头后显示 3 秒全屏蒙版倒计时。
2. 倒计时结束时，以最近约 1.1 秒有效 AU 的中位数建立个人基线；有效数据不足时继续显示蒙版等待人脸稳定。
3. 此后只要摄像头开启，就持续计算 AU 相对基线的正向差值，经 280ms 短时中位数平滑和个人噪声扣除后，转换为 AU 比例并与表情原型计算相似度；明确的新表情持续约 280ms 即切换，模糊结果需约 360ms，回到平静需约 300ms，以兼顾响应速度和防闪烁。助手说话期间也不会暂停实时计算。
4. 调试模式开启时，画面顶部显示缩小版实时 AU 差值柱状图，右上框显示当前实时表情，右下框按当前阶段显示用户输入窗口汇总，或显示用户听到具体语音段时的表情结果。
5. 基线完成后立即开始第一轮用户输入检测。以后在助手整轮播放结束时开始，在用户发送文字或语音时结束；输入阶段沿用设置中的最小时长阈值。
6. 助手开始播放时切换为听音检测。每个实际播放的语音段独立统计累计持续最久的一种非中性表情，累计不足 300ms 不记录；播放被打断时按实际播放比例保留近似文本前缀。后台为侧写保存全部合格段，普通聊天提示词只保留持续时间最长的三段。
7. 输入阶段与整轮助手播放阶段分别计算窗口内有效心率样本的平均值；有效样本不足三次时不记录该阶段平均心率。
8. 用户输入窗口会将同一稳定表情在不同阶段的时长先累加，再过滤累计时长低于设定阈值的非中性结果。中性不进入累计列表；整轮没有达标的非中性表情时发送中性。
9. 输入阶段达标结果按累计时长从高到低排列，最多发送两项；时长四舍五入到 100 毫秒。同一时刻的模糊结果以“或”连接并作为独立组合累加，例如：`你看到用户回复你时的表情为：3200毫秒开心，1800毫秒惊讶`。

## 算法与边界

- 不使用云端直接返回的情绪标签、概率或置信度。
- AU43 可被云端返回，但不参与表情分类。
- 顶部调试图仍显示 AU43；图中绿色为高于个人基线，红色为低于个人基线，数值为平滑后的 `当前 AU − 基线 AU`。
- 顶部 AU 图和右侧两个表情框仅在主应用调试模式开启时出现；关闭调试模式不会停止识别或 prompt 注入。
- “A或B”作为一个独立模糊组合累加，时长不拆分给 A 或 B。
- 无人脸或结果过期的时间不计入有效时长。
- 摄像头图像只以 JPEG 二进制帧发送给 AIE 实时 WebSocket，不在本地保存。
- 上传采用 12 FPS、JPEG 质量 0.7；浏览器发送缓冲超过 64KB 时直接跳过当前帧，避免网络或云端变慢后继续排队处理过时画面。
- 网络、协议、摄像头、空结果和识别异常都在模块内降级，不阻止聊天消息发送。
- 短暂断线会自动重连；鉴权恢复后清除重连提示并继续使用已有个人基线。

## 文件

- `optional-feature.json`：可选模块声明及运行参数。
- `frontend-src/index.tsx`：摄像头、屏幕共享、浏览器面板与主项目轮次桥接。
- `frontend-src/main.ts`：Electron 屏幕捕获 IPC；无本目录时由主项目空实现替代。
- `frontend/`：动态加载的 WebSocket、JPEG、AU 推断、轮次汇总和显示运行时。
- `backend_context.py`：摄像头上下文和浏览器工具状态扩展。
- `web_tool/`：浏览器自动化的本地查看页面；只有摄像头模式挂载 `/web-tool`。
- `emotion_camera/`：AK/SK 取临时 Token、WSS 云端连接和本机 WebSocket 转发代理。
